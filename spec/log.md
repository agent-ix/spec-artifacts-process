# Update Log

## History

* **2026-08-18** — **CR-006**: new **FR-008** gives `Finding` a body contract and an escape-cause classification (agent-ix/spec-artifacts-process#36). Escape analysis is the only *empirical* validation of a completeness claim — every other signal this module produces says how much was written or verified, and a distribution of real escaped defects says which layer is actually leaking.

  The infrastructure half-existed and could not have worked. `Finding` was a declared artifact type with `allowed_links`, a frontmatter schema, and a `review` archetype whose composition already expected Finding children — but **no `body_extraction` and no skeleton**, so nothing emitted one and nothing could have been aggregated if it had. It now requires a `Summary` and a `Classification` table carrying `Escape Cause | Detected In | Traces`, and ships `skeletons/Finding.md`.

  **`Escape Cause` is a four-way partition of which layer leaked**: `missing-requirement` (nobody wrote it), `wrong-requirement` (written, said the wrong thing), `correct-requirement-no-evidence` (right requirement, nothing verified it), `implementation-bug-despite-evidence` (right requirement, real evidence, wrong code). The fourth is the one worth watching — the only cause that does not indict the specification, and the only one a green Test Matrix would have called healthy, which makes its share of the distribution the honest measure of what the rest of this module is worth. It is orthogonal to `SpecReview.Severity`, which classifies by reader action rather than origin; CON-2 forbids collapsing them.

  **The id defect this fixes: one concept had three shapes and none agreed.** `defaults.id_pattern: Finding-{next:03d}` minted `Finding-001`; the archetype's own frontmatter schema requires `^[A-Z]{2,4}-[0-9]+$` and *seven letters is not two-to-four*, so **every id the default pattern produced failed the archetype's own schema** — a Finding authored the standard way could not validate. `SpecReview`'s findings table asserted a third form, `^FND-\d+$`. The pattern becomes `FND-{next:03d}`, which satisfies both; this is a unification onto the form already asserted, not a fourth spelling. TC-063 asserts the property directly — that whatever `id_pattern` mints validates against the schema — so the class of defect cannot recur silently on another archetype.

  Also corrected: `spec/spec.md` claimed **9 artifact types**; the manifest declares **13**.

  The `body_extraction` widening guard (TC-017) required a deliberate line for `Finding`, which is the guard working as designed — it exists to catch a contract arriving by accident. Matrix: TC-060..TC-064, TC-017 extended.

* **2026-08-17** — **CR-005**: two catalog entries added and the criticality question settled (agent-ix/spec-artifacts-process#43). quire-rs **v0.30.0** began reporting a declared method this catalog does not carry (FR-054-AC-11), and the first sweep — quire-rs' own 20 NFR `Measurement and Evaluation` tables, **55 rows, 17 distinct strings** — showed the `Method` column doing four jobs at once. Fifteen of the seventeen named something the catalog already had, under a different word: a **tool** (`Proptest`, `` `cargo-mutants` ``, `Criterion Benchmark`, `Fuzz Run`, `loom Exhaustive Interleaving` — and `deterministic-simulation` already lists loom in its own `tooling`), a **class synonym** (`Unit Test`, `Static Inspection`), or a **cadence** (`CI Gate` ×11, `Scheduled CI Gate` ×4, which say *when* a check runs and belong to the suite registry's schedule). FR-007 now carries the mapping table so a repository's sweep is a lookup rather than a judgement call, and **AC-10** stops this catalog making the same conflation the cells did.

  Two of the seventeen were real, and are added rather than forced into a near neighbour — a catalog whose nearest entry is wrong advises worse than one that admits the gap (**AC-9**, TC-056):

  - **`compile-time-check`** (Analysis / Compile) — the property is encoded so a violation does not build. `#![forbid(unsafe_code)]` is not `static-quality`, which measures a weakness over source, and not `design-by-contract`, which checks an executable annotation wherever it runs. There is nothing to run.
  - **`dynamic-analysis-sanitizer`** (Analysis / Integration) — TSAN, ASAN, Miri. Not `static-quality` (it executes), not `fuzzing` (it generates no input), not `fault-injection` (it induces nothing). The catalog had **no dynamic-analysis entry at all**, which is a real hole in a 29119-4-shaped registry rather than a quire-rs-specific need.

  **Criticality: already answered upstream.** This module declares no `criticality_column`, so every obligation the ecosystem derives carries none — and quoin's auditor hardcoded a `P0` multiplicity rule against it, a rule that could never fire. quire-rs [FR-053](ix://agent-ix/quire-rs/FR-053) already specifies the arrangement ("criticality is genuinely optional today … declaring one is a module's choice"), so the correction belonged in quoin rather than here. What is worth recording is *why* the column cannot simply be added: the ISO acceptance-criteria contract asserts exactly `ID | Criteria | Verification` with no `optional_columns`, and the engine's column assert is exact equality, so a fourth column fails validation — adding criticality is a `spec-artifacts-iso` change first, not an authoring habit. `Priority` exists only on the Test Matrix row, where it rates the **test** rather than the requirement. FR-007 records this and states that until the contract changes a consumer must not assume any obligation carries a criticality. Matrix: TC-056, TC-057.

* **2026-08-17** — **FR-007** (new FR): the **verification-method catalog content** — 31 methods as module data conforming to quire-rs FR-054 (agent-ix/spec-artifacts-process#35, epic agent-ix/quire-rs#81 P1). Choosing how a requirement gets verified is the core of a testing plan, and that knowledge was prose in three disconnected places: IADT lived in two spec-artifacts-iso lint rules, techniques in `traceability.vocabularies.test_type`, and quoin's `spec-evidence-analysis` skill assigned a method per requirement from a **skill-local table that no manifest declared and no code read**. The seed set is the **full sweep**, not a starter subset — 21 Test, 7 Analysis, 1 Inspection, 2 Demonstration — because a catalog shipping half the techniques teaches the advisor the other half do not exist, and an absent entry reads as "not applicable" rather than "not yet written". `evidence_kind` is drawn from the declared `test_type` vocabulary and is **method-class-shaped, never per-tool**: the tool lives in the suite registry's own `tool` column, so semgrep, an SBOM generator and a DAST scanner need no vocabulary entries of their own — without that split every adapter quoin adds would push a new term into a vocabulary three other things already read. Applicability rules use this module's own axes (`property_shapes`, `characteristics`, `object_types`), which the engine stores and never interprets; they are what make the interesting advice reachable — an `attack_surface` object suggests DAST, temporal phrasing suggests runtime monitoring or model checking, a reliability NFR suggests fault injection, a concurrency shape suggests deterministic simulation. None of those are reachable from `Verification: Test` defaulted by habit.

  **The reconciliation #35 asked for is partial, and deliberately so.** The catalog single-sources the *method* axis for consumers, through quire-rs's derived `verification_method` / `verification_class` lookups. The *kind* axis is still three literal lists — catalog, Test Matrix `Type`, suite registry `Evidence Kind` — because `from_vocabulary` was deferred (quire-rs#146); TC-050 is what keeps them honest until it lands.

  **The FR-035 gate earned itself again.** Declaring the block failed this repo's own suite on `Additional properties are not allowed ('verification_catalog' was unexpected)` — the key the engine accepts and the contract had never heard of. Before iso CR-002 that check skipped in silence. Fixed upstream in spec-artifacts-iso **v0.11.0** (FR-001 CR-003) and consumed here. Matrix: TC-048..TC-054. Closes agent-ix/spec-artifacts-process#35.

* **2026-08-17** — **FR-006** (new FR): the **evidence-layer archetypes**, `SuiteRegistry` and `Inspections` — the authored half of the ADR-0011 evidence store (agent-ix/spec-artifacts-process#34, epic agent-ix/quire-rs#81 P1). The store splits by who writes it: authored → markdown validated as a document, machine-transcribed → JSON that is typeless and corpus-invisible by design. The JSON half needs no archetype and gets none; the markdown half needs both, because a suite registry nothing validates is a list of commands nobody checks. `SUITE-N` is a **structured, doc-scoped, never-renumbered** id rather than a kebab slug — everything joins on it (run directories, bindings, freshness) and a policy-immutable semantic string is exactly what produced the 1,014 dead trace tags (quire-rs#72); the suite's name and command live in their own columns, where they can change without breaking a join. `Evidence Kind` draws from the **same** declared `test_type` vocabulary as the Test Matrix `Type` column and the obligation record's method (CR-015: one vocabulary, three uses), with the tool in its own column so a tool-specific report — semgrep, SARIF, an SBOM — needs no vocabulary entry of its own. That vocabulary is **restated rather than referenced**, a known debt: `column_choices` takes a literal list and `from_vocabulary` was deliberately deferred (quire-rs#146), so TC-042 is what keeps the copies honest until it lands.

  **Both documents live under `spec/`, which corrects a premise in agent-ix/quoin#79.** That design places `evidence/` at the repository root on the grounds that "corpus membership is type-driven post-quire-rs#73, so quire validates them wherever they live". **[RAN]** it: quire-rs CR-045 bounds the document walk to `<scope>/spec`, and #73 made membership type-driven *within* the walked root, not everywhere on disk. A typed, well-formed `evidence/suites.md` at the repository root minted **nothing** and was reported nowhere; the identical file at `spec/evidence/suites.md` was walked, validated, minted its ids and had its references reconciled. A registry that looks authoritative while being checked by nothing is the "green matrix over dead links" failure reproduced inside the store built to prevent it. Filed on quoin#79 rather than silently overridden.

  Two smaller calls. Neither archetype declares `allowed_links`: these documents are joined by declared **trace** references, not edge verbs, and declaring `references` would have added two more `UnknownEdgeType` warnings to every repo on this module for nothing — measured at zero evidence-layer mentions for a non-adopting repo (TC-047). And the FR-003 scope guard was widened by two explicit entries rather than loosened, so a contract arriving by accident still costs a deliberate line. Matrix: TC-040..TC-047. Closes agent-ix/spec-artifacts-process#34.
